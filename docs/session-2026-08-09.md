## Goal (as stated)

Set up a WiFi "reflector" that sends Balmar data to Signal K over UDP.
New project; hardware: Pi + "PiCAN" hat, Balmar shunt and display.

## Timeline

1. **User:** new project; build an installable Python package for a Pi
   with a PiCAN hat. **Claude:** scaffolded `ballmar-reflector`
   (pyproject, src layout) assuming NMEA 2000/CAN; web search found no
   public SmartLink decode.
2. **User:** "Signal K plugin likely has the decode, I just need to send
   it over WiFi." **Claude:** pivoted to a raw reflector design (no
   decoding on the Pi), Yacht Devices RAW over UDP.
3. **User:** Pi is at 192.168.4.70, RS-485 powered, display active.
   Alpine Linux ("rpcan2"), user `kgodwin`. **Claude:** added SSH key
   access (user ran `ssh-copy-id`, later added root), surveyed system:
   Alpine 3.23, `can0` UP at 500k, **zero frames / zero errors** —
   CAN bus electrically silent. Wrote OpenRC service files (Alpine has
   no systemd).
4. **Claude:** found `/dev/ttySC0`/`ttySC1` (sc16is752 overlay) — the
   hat is a **Waveshare RS485 CAN HAT (B)** (user confirmed with wiki
   link; SmartLink wired to RS485_0 A/B, no ground). Sniffed ttySC0:
   **live traffic at 115200 8N1**, ~150 B/s. CAN abandoned.
5. **Claude:** cracked framing from a 60 s capture:
   `CD | addr | cmd | len | payload | checksum` (additive, frame sums
   to 0 mod 256); 1,659/1,659 frames parsed with 0 stray bytes.
   Display polls shunt (addr 0x02) at ~5.4 Hz; every ~2.7 s requests
   the displayed page via cmd 0x15; SOC page 0x03 = 100 matched the
   display. Status byte 0x42 with heartbeat bit 0x04 pulsing ~4.8 s.
   Flagged the pre-existing "Modbus RTU @ 9600" notes in the decode doc
   as contradicted by observation (kept below the verified section).
6. **User cycled display pages during a 15-min capture** (volts 13.3,
   amps 0.0, SOH blank, time-left blank). **Claude:** mapped
   `0x05` = voltage in **mV** (13272 ≈ 13.3 V), 0x0A/0x0B/0x0C return
   −1 = "not available" (blank pages), amps screen polls 0x04+0x32.
   Bonus: cmd 0x04 identity read returns bank name **"BANK-01"**.
7. **User ran a load test** (0 → −0.3 → −0.4 → −0.5 A on display)
   during a second capture. **Claude:** **`0x06` = current in mA,
   signed** — trace followed the staircase exactly (−240/−340/−380/
   −480/−520/−580). 0x04 stayed −1 (unknown), 0x32 constant
   (config/flags).
8. **Claude:** rewrote the package for reality: SmartLink serial parser
   (`smartlink.py`), Signal K delta/UDP (`signalk.py`), daemon
   (`app.py`) with passive mode, `--poll` (Pi as bus master — needed
   once the display is removed; poll frames are byte-identical to the
   display's), `--map addr=path` for multiple devices, `--dump`
   discovery mode. Stdlib only. Parser validated against both captures
   (24k + 16.5k frames, 0 bad bytes); pip install + CLI smoke-tested.
9. **Live smoke test on the Pi:** `--dump` decoded real-time current
   (−480 mA while display showed −0.5 A). ✔
10. **User:** real target is **two MC-618 regulators** (Balmar IDs 0/1)
    on the boat; wants them as separate Signal K sources — handled by
    `--map` since every frame carries the device address.
11. **Git:** repo initialized, committed (`dee10f8`), user pushed to
    `github.com/kurt-cb/pi-balmar` (public). Workstation SSH keys are
    not on GitHub, so pushes come from the user's terminal.
12. Wrap-up: created this log + `CLAUDE.md` with the boat plan.

# Part 2 (same day, evening) — WiFi, Pi 3B+ swap, master mode, live to the boat

1. **WiFi prep:** boat WiFi (`kghome-lte`) extracted from the boat Pi's
   NetworkManager profiles; added to rpcan2's `wpa_supplicant.conf`
   (hash cross-verified) along with `totaldns-uplink`. Discovered
   rpcan2 is a **sys-mode** Alpine install — no `lbu commit` needed.
2. **No radio:** the "Pi 4" turned out to be a **CM4 on a Waveshare
   CM4-IO-BASE-B with no WiFi chip** (SDIO probe dead, BT UART dead,
   user visually confirmed missing chip). SD card + hat moved to a
   **Pi 3B+** — WiFi came up on first boot with the staged config;
   RS-485 kept working unchanged. New bench IP: eth0 192.168.4.89,
   wlan0 192.168.1.180 / fd00:1::151.
3. **Master mode:** with the display detached, bare page reads went
   unanswered — the shunt idles after bus silence. Mimicking the
   display's full pattern (status polls + page requests) wakes and
   holds it. Rate sweep: fine at 25 req/s, but **≥10 ms between TX
   frames is mandatory** (0 ms → 0% answered). Display timing measured:
   186 ms cycle. Poll mode updated accordingly; service switched to
   master mode. Timing tables in `docs/rs-485 decode.md`.
4. **`--console`** debug mode added (live values, no daemon/UDP), plus
   `tools/uartcap.py` checked into the repo.
5. **Discovery + config:** `--discover` scans all 256 addresses
   (status poll + cmd 0x04 identity) — bench shows `0x02 BANK-01`.
   Production config `/etc/ballmar-reflector.json` keys devices by
   their **stored name** with `report`/`prefix`/`pages`; startup scan
   resolves names→addresses; unknown devices logged, missing ones
   rescanned every 60 s.
6. **Live to the real boat:** Signal K 2.20.0 at kgboat-nmea2000
   (boat LAN 192.168.12.72, VPN overlay fd00:108::6010). Bank **1** is
   owned by an N2K source (addr 101) — ours goes to bank **0**.
   Found signalk's **UDP input binds IPv4-only** (confirmed by netstat)
   while the bench→boat path is routed IPv6 → added a **TCP server
   transport** (`"listen"`): Signal K dialed the Pi (fd00:1::151:4123)
   and **bank 0 went live on the real boat** (13.224 V / −0.44 A /
   SOC 1.0) next to the factory N2K bank.
7. **End state:** TCP demo retired; reflector reconfigured for the
   boat move — UDP to `kgboat-nmea2000.lan:4123` (sender now prefers
   IPv4 resolution), master mode, BANK-01 → `electrical.batteries.0`.
   The Signal K server keeps two prepared connections: UDP
   `balmar-reflector` (enable on the boat) and TCP
   `balmar-reflector-tcp` (bench demos only). Manual updated with the
   transport how-to. "Network congestion" banner in the admin UI =
   browser-over-LTE WebSocket lag; enable WS compression in Settings.
